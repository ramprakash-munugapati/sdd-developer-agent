# sdd-developer-agent

Spec Driven Development Based Developer Agent. Translates approved `SPEC.md`, `PLAN.md`, and `TASKS.json` into production-ready code, tests, and evidence.

---

## Overview

This agent implements the full SDD developer lifecycle defined in the specification:

- **Phase 1 – Intake & Readiness** – Validate SDD artifacts
- **Phase 2 – Task Selection** – Pick the next executable task
- **Phase 3 – Implementation** – Scaffold code & tests
- **Phase 4 – Validation & Evidence** – Run checkstyle → tests → JaCoCo
- **Phase 5 – Review & Merge** – Generate PR template
- **Phase 6 – Continuous Monitoring** – Track metrics across tasks

All code traces back to requirements (`REQ‑XXX`) via task IDs (`TASK‑NNN`).

---

## Prerequisites

- Java 17+ & Maven 3.9+
- `SPEC.md`, `PLAN.md`, and `TASKS.json` in the project root
- Maven plugins: `checkstyle`, `maven-surefire`, `jacoco` (already configured in `auth-service/pom.xml`)

---

## Quickstart

```bash
# 1️⃣ Validate SDD artifacts
mvn sdd:intake

# 2️⃣ Scaffold the next task & create a feature branch
mvn sdd:start

# 3️⃣ Implement the task (code + tests) in the new branch

# 4️⃣ Run the full verification pipeline
mvn sdd:verify   # checkstyle → tests → JaCoCo; fails fast if coverage < 80%

# 5️⃣ Generate a PR template with evidence
mvn sdd:pr
```

---

## Example Workflow

```bash
mvn sdd:intake          # ✅ Intake: all three SDD artifacts present
mvn sdd:start           # 🚀 Starting task: TASK-001 – Implement user authentication
# ... write code (AuthenticationController, SecurityConfig) & tests ...
mvn sdd:verify          # ✅ verify: ALL GATES PASSED
mvn sdd:pr              # ✅ PR template written to PULL_REQUEST_TEMPLATE.md
```

After `mvn sdd:verify`, evidence JSON files appear under `target/sdd-evidence/<task-id>.json`. The PR template links `REQ‑A1`/`REQ‑A2`/`REQ‑A3`/`REQ‑A4`, lists changed files, and shows gate outcomes.

## Adding a New Task

1. Edit `TASKS.json` – add a new task entry with `id`, `title`, `status: planned`, `dependencies`, and `validation.threshold`.
2. Run `mvn sdd:intake` to validate.
3. Run `mvn sdd:start` – the agent will create `feature/TASK-NNN-<brief-title>` and scaffold stubs.
4. Implement, test, then `mvn sdd:verify` → `mvn sdd:pr`.

## Evidence Artifacts

| Gate | Report Location | Meaning |
|------|-----------------|---------|
| Checkstyle | `target/checkstyle-result.xml` | 0 violations ✅ |
| Tests | `target/surefire-reports/TEST-*.xml` | All tests green ✅ |
| JaCoCo | `target/site/jacoco/jacoco.xml` | Line coverage ≥ 80 % ✅ |
| Per‑task evidence | `target/sdd-evidence/<task-id>.json` | Gates, timestamps, report paths |

## Developer Tips

- Run `mvn verify` locally to replicate the agent’s gate order (checkstyle → test → jacoco).
- Use `mvn dependency:tree -q \| grep security` to inspect Spring Security versions.
- If a gate fails, `mvn sdd:verify` will throw a `MojoExecutionException` with the reason (e.g., “Line coverage 72% < 80%”).
- Commit messages should follow: `TASK-001: Implement user authentication (REQ-A1, REQ-A2)`.

---

If you need to reset a failed task, use `git revert <last‑good‑commit>` or delete the feature branch and re‑run `mvn sdd:start`.
